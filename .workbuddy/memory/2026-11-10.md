## 首页新增应用截图轮播

- 用户提供 5 张 1080×2400 安卓截图（`src/assets/`）：today / ask / memory / todo / config，对应 App 底部导航「今天 / 问问 / 记忆 / 待办 / 设置」。原文件名 `menmery.jpg` 拼错，已改为 `memory.jpg`。
- 轮播插在首屏 hero 与四张功能卡片之间（`src/pages/index.astro` 第一个 `</section>` 之后），纯 Alpine 内联 `x-data`，不注册 `Alpine.data`——因为 `Alpine.start()` 在 Layout 里执行，`Alpine.data` 注册时机不可靠。
- 实现要点：`overflow-x-auto` 横向轨道 + 左右箭头 + 指示点；卡片宽度 236 / sm 262 / lg 276（1440 下正好露出第 5 张边缘，提示可滑）；桌面端 5s 自动播放，hover/focus 暂停，移动端（`pointer: coarse`）不自动播放；`prefers-reduced-motion` 直接跳转。
- 踩坑一：`snap-x snap-mandatory` 与程序化 `scrollTo` 互相抢位置，连点两次会跳过一张。去掉 scroll-snap，改自己用 rAF 做 420ms ease-out 滚动，并在 `go()` 里 `cancelAnimationFrame` 掉上一段动画（原生 smooth 滚动叠加是跳张的真正原因）。
- 踩坑二：`sync()` 用 `offsetLeft` 判断最近卡片会算错，因为 track 不是 offsetParent，`offsetLeft` 含页面前置偏移。改用 `child.getBoundingClientRect().left - track.getBoundingClientRect().left`。
- 踩坑三：验证时出现「跳两张 / 回绕到 1」，实际是 5s 自动播放插进来的，不是逻辑 bug。测试脚本里先 `dispatchEvent(new MouseEvent('mouseenter'))` 把 `paused` 置 true。
- 图片走 `astro:assets` 的 `<Image>`：`widths={[236,262,276,552]}` + `sizes` + webp q80，总量 2.2MB → 约 300KB（单张 7–94KB）。
- 验证：CDP 实测点击序列 0→1→2→1→4(末张 scrollLeft 902)→0 全部正确；390 / 1024 / 1440 无横向溢出，`document.scrollWidth === clientWidth`。

## 视觉系统重做（Awwwards 级尝试）
